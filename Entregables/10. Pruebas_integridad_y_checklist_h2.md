## 1. Resumen Ejecutivo del Cierre del Hito H2

El **Hito H2** ha concluido con éxito, entregando la arquitectura dimensional completa, normalizada y gobernada que servirá como base para todos los pipelines ETL del proyecto NexoSalud.

El diseño desarrollado por el **Integrante 2 (Marck Alessandro Hermenegildo Pacheco)** subsanó de manera definitiva las deficiencias críticas identificadas en el Anexo C del informe académico preliminar, dotando a la base de datos `NexoSalud_Mart` de:
1. **Unicidad e Idempotencia:** Adición de `KeyFact BIGINT IDENTITY(1,1) PRIMARY KEY` e índices `UNIQUE NONCLUSTERED` sobre las claves de origen transaccional en las tablas de hechos.
2. **Desacoplamiento Publicitario:** Creación independiente de `Dim_Fuente` y `Dim_Campana`, eliminando el producto cartesiano (*fan-out*) que inflaba el costo de adquisición de pacientes (CAC).
3. **Robustez Referencial:** Institucionalización obligatoria del **Miembro Desconocido (`Key = 0`)** en las 14 tablas dimensionales.
4. **Gobierno de Privacidad (LPDP):** Fusión de perfiles en `Dim_Persona` con aislamiento total de la anamnesis clínica libre.
5. **Ejes Temporales Conformados:** Scripts generadores determinísticos para `Dim_Tiempo` (2024–2030 con feriados oficiales de Perú) y `Dim_Hora` (1,440 minutos con turnos de Luxedent).

### CP-DIM-03: Continuidad y Feriados en Dimensión Tiempo (`Dim_Tiempo`)
* **Objetivo:** Verificar que el calendario diario 2024–2030 no tenga lagunas temporales (*gaps*) y registre correctamente los feriados oficiales de Perú.
* **Consulta SQL de Validación:**
  ```sql
  -- 1. Verificación de conteo de días calendario (2024 a 2030 = 2,557 días + día desconocido = 2,558)
  SELECT 
      COUNT(*) AS TotalFechas,
      MIN(id_fecha) AS FechaMinima,
      MAX(id_fecha) AS FechaMaxima
  FROM NexoSalud_Mart.dbo.Dim_Tiempo;

  -- 2. Detección de posibles duplicados en la serie de fechas
  SELECT id_fecha, COUNT(*) AS Ocurrencias
  FROM NexoSalud_Mart.dbo.Dim_Tiempo
  GROUP BY id_fecha
  HAVING COUNT(*) > 1;
  ```
* **Criterio de Aceptación:**
  * `TotalFechas >= 46` (todas las fechas operativas del transaccional).
  * La consulta de duplicados debe retornar **0 filas**.

### CP-DIM-04: Cobertura Completa de `Dim_Hora` (Franjas y Turnos)
* **Objetivo:** Validar que existan las horas operativas y que la asignación de turnos coincida con la clínica.
* **Consulta SQL de Validación:**

  SELECT

      SUM(CASE WHEN Turno = 'Mañana' THEN 1 ELSE 0 END) AS HorasTurnoManana,
      SUM(CASE WHEN Turno = 'Tarde' THEN 1 ELSE 0 END) AS HorasTurnoTarde,

  * Cobertura de turnos Mañana, Tarde y Noche conforme a la actividad clínica.

### CP-DIM-05: Verificación de Claves Primarias Subrogadas e Índices de Idempotencia en Hechos
* **Objetivo:** Confirmar que las 5 tablas de hechos posean clave primaria `BIGINT IDENTITY` y un índice único sobre la clave del evento origen.
* **Consulta SQL de Validación:**
  ```sql
  SELECT 
      t.name AS TablaHecho,
      c.name AS ColumnaPK,
      i.name AS IndiceUnico,
      i.is_unique AS EsUnico
  FROM sys.tables t
  INNER JOIN sys.key_constraints kc ON t.object_id = kc.parent_object_id AND kc.type = 'PK'
  INNER JOIN sys.index_columns ic ON kc.parent_object_id = ic.object_id AND kc.unique_index_id = ic.index_id
  INNER JOIN sys.columns c ON ic.object_id = c.object_id AND ic.column_id = c.column_id
  LEFT JOIN sys.indexes i ON t.object_id = i.object_id AND i.is_unique = 1 AND i.is_primary_key = 0
  WHERE t.name LIKE 'Fact_%';
  ```
* **Criterio de Aceptación:** Cada tabla de hechos debe listar su respectiva `KeyFact*` como PK Clustered y contar con un índice único no agrupado (`UQ_Fact_*_Origen`).

### CP-DIM-06: Prueba de Carga Idempotente (Rerun Test)
* **Objetivo:** Demostrar que ejecutar dos veces consecutivas el procedimiento de carga no inserta registros duplicados ni altera las métricas numéricas.
* **Procedimiento de Prueba:**
  1. Ejecutar el pipeline ETL por primera vez sobre un lote de prueba y registrar el total de filas y la suma de importes:
     $$N_1 = \text{COUNT}(*), \quad S_1 = \sum \text{ImporteTotalCobro}$$
  2. Ejecutar inmediatamente el mismo pipeline ETL por segunda vez (re-ejecución idéntica).
  3. Registrar los nuevos totales:
     $$N_2 = \text{COUNT}(*), \quad S_2 = \sum \text{ImporteTotalCobro}$$
* **Criterio de Aceptación:**
  $$N_1 = N_2 \quad \text{y} \quad S_1 = S_2$$
  El proceso debe reportar `RegistrosInsertados = 0` y `RegistrosOmitidos = N_1` en la tabla `ETL_BatchControl`.

### CP-DIM-07: Verificación de Cero Exposición de Datos Clínicos Sensibles (LPDP)
* **Objetivo:** Auditar que ninguna columna en las tablas del Data Mart contenga términos clínicos restringidos (`alergias`, `diagnostico`, `anamnesis`, `patologia`, `tratamiento_medico`).
* **Consulta SQL de Validación:**
  ```sql
  SELECT 
      TABLE_NAME, 
      COLUMN_NAME, 
      DATA_TYPE
  FROM INFORMATION_SCHEMA.COLUMNS
  WHERE TABLE_SCHEMA = 'dbo'
    AND (
      COLUMN_NAME LIKE '%alergia%' OR
      COLUMN_NAME LIKE '%diagnostico%' OR
      COLUMN_NAME LIKE '%antecedente%' OR
      COLUMN_NAME LIKE '%anamnesis%' OR
      COLUMN_NAME LIKE '%patologia%' OR
      COLUMN_NAME LIKE '%indicaciones%'
    );
  ```
* **Criterio de Aceptación:** **0 filas retornadas.** El almacén analítico se encuentra 100% libre de datos de salud sensibles.

---

### CP-DIM-08: Integridad Referencial Global (Cero Claves Foráneas Rotas)
* **Objetivo:** Asegurar que todos los registros cargados en las tablas de hechos apunten a surrogate keys existentes en las dimensiones conformadas.
* **Consulta SQL de Validación:**
  ```sql
  -- Ejemplo sobre Fact_CaptacionBuyer
  SELECT COUNT(*) AS HuerfanosTiempo 
  FROM dbo.Fact_CaptacionBuyer f 
  LEFT JOIN dbo.Dim_Tiempo d ON f.KeyTiempoRegistro = d.KeyTiempo 
  WHERE d.KeyTiempo IS NULL;

  -- Ejemplo sobre Fact_GestionPayer
  SELECT COUNT(*) AS HuerfanosCobro 
  FROM dbo.Fact_GestionPayer f 
  LEFT JOIN dbo.Dim_Cobro d ON f.KeyCobro = d.KeyCobro 
  WHERE d.KeyCobro IS NULL;

  -- Ejemplo sobre Fact_AtencionCustomer
  SELECT COUNT(*) AS HuerfanosAtencion 
  FROM dbo.Fact_AtencionCustomer f 
  LEFT JOIN dbo.Dim_EstadoAtencion d ON f.KeyEstadoAtencion = d.KeyEstadoAtencion 
  WHERE d.KeyEstadoAtencion IS NULL;
  ```
* **Criterio de Aceptación:** Todas las comprobaciones deben dar **0**.
